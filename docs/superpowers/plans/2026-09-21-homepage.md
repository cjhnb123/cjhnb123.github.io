# Joel_Chen JH / NOTES Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Build and verify a responsive Jekyll homepage that faithfully implements the approved Joel_Chen JH / NOTES design on the blog/homepage branch.

**Architecture:** GitHub Pages renders one semantic Liquid template from content stored in _data/home.yml. Focused SCSS partials implement design tokens, shared rules, desktop layout, and responsive behavior; Node 24 contract tests validate source and generated HTML, while GitHub Actions supplies the GitHub Pages Ruby/Jekyll environment that is unavailable in the current local workspace.

**Tech Stack:** Jekyll 3.10.0, github-pages 232, Liquid 4.0.4, Ruby 3.3.4, SCSS, HTML5, Node.js 24 built-in test runner, GitHub Actions

**Spec:** docs/superpowers/specs/2026-09-21-homepage-design.md

## Global Constraints

- Work only on branch blog/homepage; do not modify main directly.
- Deliver one homepage only; do not add article, topic, or standalone about pages.
- Do not add a third-party theme, client-side JavaScript, remote fonts, search, comments, analytics, subscriptions, dark mode, or non-GitHub-Pages plugins.
- Use site.title from _config.yml as the only brand source for the document title, header, and footer.
- Keep editable homepage copy in _data/home.yml.
- Render only two semantic article items; render row 03 as an aria-hidden decorative placeholder outside the article list.
- Preserve only the gray and red shapes in the upper artwork; do not restore the removed blue rounded shape, yellow top dot, or black vertical line.
- Use the approved colors exactly: #f8f7f3, #f2f1ed, #111111, #6c6b68, #1769e8, #e8372f, and #f5be20.
- Use breakpoints exactly: desktop at 1025px and above, tablet from 768px through 1024px, mobile below 768px, and compact mobile below 420px.
- Use no fixed full-page height and allow content height to grow naturally.
- Validate with bundle exec jekyll build --strict_front_matter and strict Liquid variables, filters, and error mode.
- Treat the approved 1586 × 992 PNG identified in the spec as the desktop visual reference.
- GitHub Pages version pins come from the official https://pages.github.com/versions.json snapshot checked on 2026-09-21.

## Review Focus

1. Missing optional article fields must not create empty titles, dates, anchors, or semantic list items; Task 2 and Task 3 pin the data and markup behavior.
2. Exactly 1024px must use the tablet layout and 1025px must use the desktop layout; Task 6 pins both media-query boundaries.
3. Deleted upper-artwork motifs must stay absent; Task 5 checks selectors and the final visual pass checks pixels.
4. Every page anchor must resolve to one unique ID and generated HTML must contain no unresolved Liquid; Task 7 validates the built document.
5. Long Chinese text and system-font differences must not create horizontal overflow at 1586px, 1024px, or 390px; Task 6 adds defensive CSS and Task 7 performs viewport checks.

## File Map

### Production files

- .ruby-version — pins the GitHub Pages Ruby runtime used in validation.
- Gemfile — pins github-pages 232 without adding a theme.
- _config.yml — provides site metadata, strict Liquid settings, Sass settings, and build exclusions.
- _data/home.yml — stores all editable homepage content and accent names.
- _layouts/default.html — owns the document shell, metadata, stylesheet link, skip link, header include, content slot, and footer include.
- _includes/header.html — renders the brand and three page anchors.
- _includes/footer.html — renders the brand, fixed display date, and three accent squares.
- index.html — composes the approved homepage sections from Liquid data.
- _sass/_tokens.scss — owns exact palette, typography stacks, spacing, and width tokens.
- _sass/_base.scss — owns reset, body, shared container, header, footer, focus, and motion defaults.
- _sass/_home.scss — owns the desktop homepage composition and decorative shapes.
- _sass/_responsive.scss — owns tablet, mobile, compact-mobile, and reduced-motion behavior.
- assets/css/main.scss — Jekyll Sass entry point.
- .gitignore — excludes generated and local dependency artifacts.
- README.md — documents preview and verification commands.

### Verification files

- test/homepage-contract.test.mjs — validates source-level configuration, data, structure, CSS, and accessibility contracts with Node built-ins.
- test/generated-homepage.test.mjs — validates the Jekyll-generated _site/index.html.
- .github/workflows/validate.yml — runs Node contract tests, strict Jekyll build, and generated-HTML tests on the branch and pull request.

import test from "node:test";
import assert from "node:assert/strict";
import { existsSync, readFileSync } from "node:fs";
import { join } from "node:path";

const output = "_site/index.html";
const html = existsSync(output) ? readFileSync(output, "utf8") : "";

test("Jekyll generated the homepage", () => {
  assert.equal(existsSync(output), true, "_site/index.html must exist");
  assert.match(html, /<html lang="zh-CN">/);
  assert.match(html, /<header\b/);
  assert.match(html, /<main\b[^>]*id="main-content"/);
  assert.match(html, /<footer\b/);
  assert.doesNotMatch(html, /{{|{%/);
  assert.doesNotMatch(html, /<script\b/i);
});

test("all fragment links resolve to unique IDs", () => {
  const ids = [...html.matchAll(/\sid="([^"]+)"/g)].map((match) => match[1]);
  assert.equal(new Set(ids).size, ids.length, "IDs must be unique");

  const targets = [...html.matchAll(/href="#([^"]+)"/g)].map((match) => match[1]);
  for (const target of targets) {
    assert.equal(ids.includes(target), true, `missing #${target}`);
  }
});

test("article semantics contain two articles and one hidden placeholder", () => {
  const articleItems = html.match(/<li class="article-row">/g) ?? [];
  assert.equal(articleItems.length, 2);
  assert.match(
    html,
    /class="article-row article-row--placeholder" aria-hidden="true"/
  );
  assert.doesNotMatch(html, /href="(?:#)?"/);
});

test("every generated local stylesheet exists", () => {
  const stylesheets = [...html.matchAll(/href="([^"]+\.css)"/g)]
    .map((match) => match[1])
    .filter((href) => href.startsWith("/"));

  for (const href of stylesheets) {
    const generatedPath = join("_site", href.replace(/^\//, ""));
    assert.equal(existsSync(generatedPath), true, `${href} must exist`);
  }
