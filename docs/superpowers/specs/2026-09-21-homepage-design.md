# Joel_Chen JH / NOTES 首页设计规格

- 日期：2026-09-21
- 仓库：`cjhnb123/cjhnb123.github.io`
- 目标分支：`blog/homepage`
- 状态：书面规格已确认，进入实施计划阶段

## 1. 目标

在现有空白 GitHub Pages 仓库中创建一个轻量、可维护的 Jekyll 首页，高保真还原已批准的桌面视觉稿，并提供适合手机和平板的响应式布局。首页应可直接由 GitHub Pages 构建，不依赖第三方主题、前端框架或客户端 JavaScript。

成功标准：

- 在 1586 × 992 视口下，结构、层级、色彩、比例和装饰元素与批准稿一致。
- 在 1024 × 768 与 390 × 844 视口下，无横向滚动、文字裁切、模块重叠或装饰图形变形。
- 首页内容由一个 YAML 数据文件管理，修改文案或列表项无需修改页面结构。
- Jekyll 严格构建成功，页内导航有效，生成页面不包含无效外链或资源 404。
- 合并到 `main` 后可由 GitHub Pages 从仓库根目录发布。

## 2. 范围

首版只交付首页，包含：

1. 顶部品牌与页内导航。
2. 自我介绍区。
3. 本期精选区。
4. 最新文章列表与一行编号视觉预留。
5. 正在学习区。
6. 宣言卡片。
7. 页脚。
8. 桌面、平板和手机响应式样式。

首版明确不包含：

- 文章详情页、专题页或独立关于页。
- 搜索、评论、订阅、后台管理、分析统计或深色模式。
- 客户端 JavaScript、第三方 Jekyll 主题或非 GitHub Pages 白名单插件。
- 把批准稿整张图片作为网页背景。

## 3. 技术方案

使用 GitHub Pages 原生支持的 Jekyll、Liquid、HTML 和 SCSS。页面采用服务端静态生成；运行时没有网络请求、脚本状态或后端依赖。桌面与移动端共用一份语义化 HTML，通过 CSS Grid、Flexbox、媒体查询和 `clamp()` 完成布局变化。

文件结构：

```text
cjhnb123.github.io/
├── _config.yml
├── _data/
│   └── home.yml
├── _layouts/
│   └── default.html
├── _includes/
│   ├── header.html
│   └── footer.html
├── _sass/
│   ├── _tokens.scss
│   ├── _base.scss
│   ├── _home.scss
│   └── _responsive.scss
├── assets/css/main.scss
├── index.html
├── Gemfile
└── .gitignore
```

职责边界：

- `_config.yml`：站点标题、描述、语言和 Jekyll 构建配置；`site.title` 是页头、页脚和文档标题的唯一品牌数据源。
- `_data/home.yml`：所有首页可编辑内容和强调色标识。
- `_layouts/default.html`：文档外壳、元数据和样式入口。
- `_includes/header.html`、`footer.html`：可复用的页头与页脚。
- `index.html`：首页语义结构与 Liquid 循环；不包含大段内联样式。
- `_sass/`：设计令牌、基础样式、桌面布局和响应式规则。
- `assets/css/main.scss`：只负责导入 SCSS 分层。
- `Gemfile`：锁定 GitHub Pages 兼容的本地预览依赖。

## 4. 页面组成与交互

页面按以下顺序渲染：

1. `header`：品牌 `Joel_Chen JH / NOTES` 与“文章、专题、关于”导航。
2. `main`：
   - `#about`：主标题、简介和 `READ / THINK / BUILD / SHARE`。
   - `#featured`：灰红几何图形、`本期精选`、精选标题和装饰箭头。
   - `#articles`：两条文章记录和一条无语义的编号视觉预留行。
   - `#learning`：两张学习卡片和状态说明。
   - 宣言卡片：`IDEAS / FOR A / BRIGHTER / TOMORROW` 与黄色圆弧。
3. `footer`：品牌、日期和蓝红黄三色方块。

导航均为当前页面的标准锚点：

- 文章 → `#articles`
- 专题 → `#featured`
- 关于 → `#about`

浏览器原生跳转配合 CSS 平滑滚动。没有目标页面的文章箭头是装饰元素，不创建空 `href`。首版的文章标题全部呈现为文本，不设置 URL；三个导航锚点保留可见键盘焦点样式。

## 5. 内容数据

`_data/home.yml` 负责提供以下数据组：

- `navigation`：标签、目标锚点、默认强调状态。
- `intro`：主标题、两行简介、四个英文关键词。
- `featured`：栏目标签、精选标题、编号。
- `articles`：编号、标题、日期、蓝红黄强调色。
- `learning`：学习项目及对应强调色。
- `manifesto`：四行英文宣言。
- `footer`：显示日期和色块顺序。

初始内容固定为：

- 品牌：`Joel_Chen JH / NOTES`。
- 介绍标题：`知识，在阅读与实践之间生长`。
- 介绍正文：`记录思考，整理方法，连接灵感。` 与 `在不断变化的世界里，构建一个可以长期生长的知识系统。`。
- 介绍关键词：`READ / THINK / BUILD / SHARE`。
- 精选标签：`本期精选`。
- 精选标题：`如何搭建一个长期生长的个人博客`。
- 最新文章：`01 设计系统`、`02 Linux 笔记`；两项日期均为 `2026.09.20`。
- 编号视觉预留：`03`、短线与黄色方块，不包含文章语义、标题、日期或链接，并设置 `aria-hidden="true"`。
- 正在学习：`设计系统`、`Linux 笔记`。
- 学习说明：`持续阅读`、`持续实践`、`成为更好的自己`。
- 宣言：`IDEAS / FOR A / BRIGHTER / TOMORROW`。
- 页脚日期：`2026.09.20`。

文章列表由 Liquid 循环生成，增删文章数据不需要修改 HTML。编号视觉预留使用独立的 `article_placeholder` 数据对象和非列表装饰容器，避免生成语义为空的列表项。模板在字段缺失时不输出空标题、空日期、空链接或多余分隔符。导航中的“文章”默认保留批准稿里的蓝色下划线强调；点击其他导航只执行页内跳转，不改变该静态强调状态。

## 6. 视觉系统

视觉基准是本次任务中最后确认的 1586 × 992 PNG，文件标识为 `exec-000b4847-b188-4091-b035-c43a4841a25a.png`，SHA-256 为 `17C34E5CCC500E426DADC8F251124838030AD3A3EFEF3F1A823C99BD812C9657`。实现验收使用该尺寸、文件标识和摘要锁定同一版本；规格中的结构、文案和令牌使实现不依赖把该图片作为网页资源。

颜色令牌以批准稿为基准：

```scss
$color-bg: #f8f7f3;
$color-surface: #f2f1ed;
$color-text: #111111;
$color-muted: #6c6b68;
$color-rule: rgba(17, 17, 17, 0.34);
$accent-blue: #1769e8;
$accent-red: #e8372f;
$accent-yellow: #f5be20;
```

字体采用本机回退栈，不请求在线字体：

- 展示标题与品牌：`Georgia`, `Noto Serif SC`, `Source Han Serif SC`, `Songti SC`, `SimSun`, serif。
- 导航、正文和元数据：系统 UI 字体、`PingFang SC`, `Microsoft YaHei`, sans-serif。

视觉规则：

- 页面背景使用柔和灰白色，主体文字接近黑色。
- 蓝、红、黄只作为小面积强调色。
- 上方几何区域只保留浅灰矩形和红色矩形。
- 不出现已经删除的蓝色圆角块、黄色圆点或黑色竖线。
- 最新文章与视觉预留共同保留 `01—■`、`02—■`、`03—■` 的连续编号语言。
- 顶部和底部品牌均使用 `Joel_Chen JH / NOTES`。
- 页面最大内容宽度为 1460px；更宽视口中整体居中。
- 页面高度由内容自然决定，不硬编码为单屏高度。

## 7. 响应式设计

### 桌面：宽度 ≥ 1025px

- 首屏采用介绍区与精选区双栏布局。
- 精选区内部以几何图形和标题构成横向组合。
- 下半区采用“最新文章 / 正在学习 / 宣言卡片”三栏结构。
- 以 1586 × 992 批准稿为视觉基准，逐项匹配主要分区边界、列宽关系、主标题两行排版、分隔线位置和装饰图形比例；允许操作系统字体回退造成小幅字宽差异。

### 平板：768px–1024px

- 首屏变为纵向；精选区内部仍保留可读的两列关系。
- 最新文章与正在学习组成两列；宣言卡片位于下一行并占满可用宽度。
- 字号、间距和线条长度通过 `clamp()` 缩放。

### 手机：宽度 < 768px

- 页头品牌和导航分为两行。
- 全部内容变为单栏，顺序为介绍、精选、最新文章、正在学习、宣言卡片、页脚。
- `FEATURED / 01` 从竖排改为横排小标签。
- 精选区几何图形压缩成较矮的装饰区域，文字位于其下。
- 文章日期移动到标题下方，编号、短线和色块保持为同一视觉单元。
- 宣言卡片和黄色圆弧按容器比例缩小。
- 页面水平内边距为 20px，所有内容保持在视口内。

### 小屏手机：宽度 < 420px

- 进一步降低主标题字号和模块间距。
- 保持至少 44px 的交互目标高度。
- 不隐藏任何有语义的正文内容。

## 8. 可访问性与渐进增强

- 使用 `header`、`nav`、`main`、`section`、`footer` 和顺序正确的标题层级。
- 纯装饰箭头、线条和几何形状设置 `aria-hidden="true"`。
- 文字与背景保持可读对比度；颜色不是传递编号或状态的唯一方式。
- 键盘焦点清晰可见，页内锚点预留滚动偏移。
- 导航和卡片使用 150ms 的颜色或位移悬停过渡；在 `prefers-reduced-motion: reduce` 下关闭过渡。
- 字体加载不依赖外部服务；系统缺少首选字体时使用稳定回退。

## 9. 错误处理

- YAML、Front Matter、Liquid 变量或 Liquid 过滤器无效时，严格 Jekyll 构建必须失败，停止发布。
- 可选数据字段缺失时，模板省略对应元素而不是输出空标签。
- 所有导航目标在同一页面内存在；没有未来页面的链接不提前启用。
- SCSS 编译失败、资源路径不存在或生成页面缺失均视为阻断问题。
- GitHub Pages 构建失败时不宣称已发布，先读取构建结果并修复。

## 10. 验证与验收

构建验证：

1. 在 `_config.yml` 中启用 `liquid.error_mode: strict`、`strict_variables: true` 和 `strict_filters: true`，再运行 `bundle exec jekyll build --strict_front_matter`。
2. 确认命令退出码为 0，并生成 `_site/index.html`。
3. 检查内部锚点、重复 ID、空链接和本地资源路径。

视觉验证：

1. 1586 × 992：逐区对照批准稿。
2. 1024 × 768：检查平板布局。
3. 390 × 844：检查手机布局。
4. 三个视口都检查横向溢出、文字裁切、模块重叠、异常换行和装饰图形变形。

交互与可访问性验证：

1. 使用键盘依次访问导航，确认焦点可见。
2. 确认三个导航锚点落在正确区域。
3. 确认装饰图形不进入可访问名称。
4. 在减少动态效果设置下确认页面没有必要之外的过渡。

## 11. 版本控制与发布

1. 从 `main` 当前提交创建 `blog/homepage` 分支。
2. 先提交本设计规格，再提交实现和验证相关更改。
3. 完成全部验证后创建 Pull Request，不直接修改 `main`。
4. 用户检查并合并 Pull Request。
5. GitHub Pages 从 `main` 分支根目录构建；若 Pages 尚未启用，则在仓库 Settings → Pages 中选择 `Deploy from a branch`、`main`、`/(root)`。
6. 合并后检查 Pages 构建状态与线上首页。

回退方式：在 Pull Request 合并前可以直接关闭分支而不影响线上站点；合并后如出现问题，通过回退该合并提交恢复此前只有 README 的状态。

## 12. 完成定义

只有以下条件全部满足，首版首页才算完成：

- 规格中列出的首页区域均已实现。
- 桌面视觉与批准稿保持一致，已删除的三个装饰元素没有重新出现。
- 平板和手机验收视口无布局缺陷。
- Jekyll 严格构建、结构检查和导航检查全部通过。
- 实现位于独立分支并已创建可供用户检查的 Pull Request。
- 合并后 GitHub Pages 构建成功且线上地址可访问。
